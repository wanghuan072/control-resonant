# CONTROL Resonant：布局与内容规划

沿用已确认的浅灰、黑红、宽幅游戏场景、窄体标题设计，不再次更换视觉方向。

## 页面分工

| 页面 | 玩家需求 | 内容顺序 |
| --- | --- | --- |
| 首页 | 判断网站能帮我什么、选择入口 | 首屏与游戏信息 → 六个栏目 → 三条入门路径 → Manhattan 横幅 → 四篇精选与资料 → Wiki 分类 |
| Guides | 找到具体问题的答案 | 分类头图 → 六主题筛选、关键词、信息类型、排序 → 攻略列表 → 完整主题索引 |
| Walkthrough / Builds / Bosses / Map | 围绕一种玩法深入阅读 | 主题介绍 → 精选攻略 → 对照表 → 专题说明；右侧目录与关联入口 |
| Database | 选择要查询的数据类型 | 分类入口 → 可直接跳转的条目索引 |
| 人物、物品、任务等 Wiki 分类 | 快速定位一个条目并理解用途 | 摘要与索引 → 条目说明、关键属性、玩家提示 → 深入阅读；右侧条目目录 |
| 攻略详情 | 解决一个具体问题 | 标题、摘要、基本事实 → 快速答案 → 章节、步骤或对照表 → FAQ、来源、相关攻略 |

## 六个主要内容主题

主题以 src/data/site/topics.json 为唯一分类来源，首页与攻略页共用。

1. Start here：入门、前作关系、人物与剧情。
2. Combat & enemies：战斗循环、Aberrant、能力、难度、敌人与 Boss。
3. Builds & progression：Talents、Artifacts、成长和 New Game Plus。
4. Missions & Manhattan：任务预览、World Quests、探索与流程长度。
5. PC, controls & accessibility：配置、控制、语言、Steam Deck、辅助设置与 DRM。
6. Release & buying guide：发售、平台、版本、订阅服务与单人模式。

每篇攻略归入一个主要玩家主题。保留原有 editorial category 字段和旧锚点，避免破坏已有链接。专题聚合仍可以跨主题引用文章。

## 首页内容选择

- 六个大型图片入口保持原顺序：Guides、Walkthrough、Builds、Database、Bosses、Map。
- 增加三个简短引导：新玩家、准备构筑、寻找任务路线。
- 四篇精选覆盖四个需求：入门、战斗、任务预览、PC 配置，不再以购买信息占据主要位置。
- 精选使用简短展示标题；文章完整标题和 SEO 标题不被截短。
- 首页卡片与精选排序放在 src/data/site/home.json，避免维护布局时误改文章正文。
- “精选”不称为“最新”；核验日期不冒充新闻发布时间。

## 数据展示规则

- 攻略的信息类型筛选区分 Official information、Preview analysis、Planning guide。
- 人物：身份、关系、演员、玩家提示；原作背景默认折叠，保留剧透说明。
- 物品：用途与所属游戏优先；不把背景物品当作续作可获取装备。
- 任务：任务类型、已公布预览与初代任务分开，不编造章节、等级或掉落。
- 地点：解释区域用途和已知关联，不把位置索引包装成精确可交互地图。
- 图片继续使用已有游戏素材和出处，不新增无来源场景。
- 来源链接保留在服务端 HTML 中，默认折叠以减少正文干扰；不会删除证据。

## SEO 与可访问性

- 每页一个 H1；栏目为 H2，条目与子章节为 H3，条目提示为 H4。
- 保留 canonical、描述、结构化数据、面包屑、站点地图及已有 URL。
- 列表与表格保留语义结构；折叠内容使用原生 details / summary。
- 筛选结果通过状态区域通知；无结果时提供清空筛选。
- 内容真实数量动态计算，不预设尚不存在的任务或装备数量。

## 后续数据录入门槛

未来新增任务或装备条目，应提供出处与核验日期，并明确正式版实测、官方信息或预览来源。未证实的精确数值保持缺省；不能用“待补充”空页扩大索引。正式版实测后再补充步骤、获得条件、奖励与位置。
